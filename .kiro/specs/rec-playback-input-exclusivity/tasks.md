- [x] 2. rec: 注入ポートの対称化と遮断対象の全ソース拡大
- [x] 2.1 トリガー注入ポートをアナログと対称のライフサイクルへ再形成する
  - 失敗するテストを先に書く（Red）: 注入開始で開始時点の全トリガーソースが遮断され基準状態が確立されること、注入終了で Unregister 済みソースも保持参照経由で遮断解除されること、再入時に旧スナップショットが先に解放されること
  - 注入開始は「内部終了（再入吸収）→ 開始時点の全トリガーソースをスナップショット保持 → 遮断 → 基準状態確立」の順で一体実行し、基準確立後のライブイベント割り込みを構造的に排除する
  - トリガー注入の呼び先を注入面へ切り替える（ゲート状態と無関係に機能、id 未解決の warn-once + スキップは維持）。注入終了は冪等で、表情スタックは解除時点のまま維持される
  - 旧「基準確立のみ」の操作を注入開始へ吸収する破壊的変更に伴い、利用箇所（キャラクターバインディングの構築コード・テスト Fake）をコンパイル追随させる
  - rec のトリガー注入まわりの EditMode テストが新契約で全緑になったら完了

- [x] 2.2 (P) アナログ / gaze の遮断対象を registry 登録済み全ソースへ拡大する

- [x] 3. rec: 再生サービスの排他確立・解放ライフサイクルを配線する
  - 失敗するテストを先に書く（Red）: Fake 両ポートを Begin/End カウンタ + 呼出順記録へ更新し、再生開始でトリガー → アナログの順に時系列イベント発火前へ排他確立されること、停止で同順に両解放されること、自然完了では解放されないこと
  - 再生開始はトリガー → アナログの順で排他確立してから時系列イベントを開始し、停止も同順で両解放する（部分的排他状態を定常状態として残さない。記録ロード冒頭の停止経路も同順序に乗る）
  - 自然完了（記録の最終イベント到達・開始直後の即時完了）では排他を維持し、停止指示を唯一の解放点とする。排他は常時有効で on/off 設定は設けない
  - 再生ユースケースの EditMode テストが新契約で全緑になったら完了
